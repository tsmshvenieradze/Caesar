Remarks

This stage is not registered as an IPipelineBehavior<TRequest, TResponse>. In a container set up with AddCaesar, the mediator composes it into the pipeline of each request type that has at least one post-processor, and of no other, in the documented order: inside the exception stages and the pre-processors, outside every pipeline behavior. Neither the number nor the order of AddCaesar calls changes that, and post-processors registered after AddCaesar count too. If this behavior is registered as a pipeline behavior anyway, the mediator leaves its own stage out, so the post-processors run once, at that registration's position.
